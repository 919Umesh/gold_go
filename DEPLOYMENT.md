# Deployment Guide - Render

This guide will help you deploy your Go backend and Redis service to Render with automatic deployment from GitHub.

## Prerequisites

1. **GitHub Account** - Your code repository
2. **Render Account** - Sign up at [render.com](https://render.com)
3. **Appwrite Cloud Account** - Already configured at `https://fra.cloud.appwrite.io/v1`

## Step-by-Step Deployment

### Step 1: Prepare Your Repository

1. **Commit all deployment files to your repository:**

```bash
git add .
git commit -m "Add Render deployment configuration"
git push origin main
```

The following files should be in your repository:
- `Dockerfile` - Multi-stage Docker build configuration
- `render.yaml` - Infrastructure as Code for Render
- `.env.example` - Environment variables template
- `docker-compose.yml` - Local development setup
- `.gitignore` - Ensures sensitive files aren't committed

### Step 2: Connect GitHub to Render

1. Go to [Render Dashboard](https://dashboard.render.com)
2. Click **"New +"** → **"Blueprint"**
3. Connect your GitHub account if not already connected
4. Select your repository: `919Umesh/gold_go`
5. Render will automatically detect the `render.yaml` file

### Step 3: Configure Environment Variables

Render will create two services based on `render.yaml`:
- `gold-go-backend` (Web Service)
- `gold-go-redis` (Redis Service)

**Important: Set the Appwrite API Key securely**

1. In the Render dashboard, go to your `gold-go-backend` service
2. Navigate to **Environment** tab
3. Find `APPWRITE_API_KEY` and click **"Edit"**
4. Set the value to your actual Appwrite API key
5. Click **"Save Changes"**

The API key is currently in your code but should be moved to environment variables for security.

### Step 4: Deploy

1. Click **"Apply"** to create the services
2. Render will:
   - Create the Redis service first
   - Build your Docker image from the Dockerfile
   - Deploy the Go backend
   - Connect the backend to Redis automatically
   - Assign a public URL like: `https://gold-go-backend.onrender.com`

### Step 5: Verify Deployment

Once deployed, test your endpoints:

```bash
# Health check
curl https://gold-go-backend.onrender.com/health

# Expected response:
# {"status":"healthy"}

# Test a public endpoint
curl https://gold-go-backend.onrender.com/api/v1/stocks
```

## Environment Variables Reference

The following environment variables are configured in `render.yaml`:

### Backend Service

| Variable | Description | Source |
|----------|-------------|--------|
| `PORT` | Server port | Set to 8080 |
| `APPWRITE_ENDPOINT` | Appwrite Cloud URL | `https://fra.cloud.appwrite.io/v1` |
| `APPWRITE_PROJECT_ID` | Your Appwrite project ID | From your Appwrite dashboard |
| `APPWRITE_API_KEY` | Appwrite API key | **Set in Render dashboard** |
| `APPWRITE_DATABASE_ID` | Appwrite database ID | From your Appwrite dashboard |
| `REDIS_HOST` | Redis hostname | Auto-linked from Redis service |
| `REDIS_PORT` | Redis port | Auto-linked from Redis service |
| `REDIS_PASSWORD` | Redis password | Auto-linked from Redis service |
| `WORKER_COUNT` | Background worker count | Set to 5 |
| `QUEUE_SIZE` | Job queue size | Set to 100 |
| `JWT_SECRET` | JWT signing secret | Auto-generated by Render |

### Redis Service

Redis is fully managed by Render with automatic configuration.

## Automatic Deployment (CI/CD)

With `autoDeploy: true` in `render.yaml`, your service will automatically redeploy when you push to the `main` branch:

```bash
# Make changes to your code
git add .
git commit -m "Update feature X"
git push origin main

# Render automatically:
# 1. Detects the push
# 2. Builds new Docker image
# 3. Deploys with zero downtime
# 4. Rolls back if health check fails
```

## Updating Your Flutter App

Update your Flutter app to use the Render backend URL:

```dart
// In your API configuration file
class ApiConfig {
  static const String baseUrl = 'https://gold-go-backend.onrender.com/api/v1';
  
  // Or use environment-based configuration
  static String get baseUrl {
    if (kReleaseMode) {
      return 'https://gold-go-backend.onrender.com/api/v1';
    }
    return 'http://localhost:8080/api/v1'; // Local development
  }
}
```

## Monitoring and Logs

### View Logs

1. Go to your service in Render dashboard
2. Click **"Logs"** tab
3. View real-time logs from your application

### Metrics

Render provides built-in metrics:
- CPU usage
- Memory usage
- Request count
- Response times

### Health Checks

Render automatically monitors your `/health` endpoint:
- Checks every 30 seconds
- Restarts service if unhealthy
- Sends alerts on failures

## Scaling

### Free Tier Limitations
- Services spin down after 15 minutes of inactivity
- First request after spin-down takes ~30 seconds
- 750 hours/month free

### Upgrade to Paid Plan

For production use, upgrade to a paid plan:

1. Go to service settings
2. Click **"Upgrade"**
3. Select a plan (Starter: $7/month, Standard: $25/month)

Benefits:
- No spin-down
- More CPU/RAM
- Custom domains
- Better support

## Custom Domain (Optional)

1. Go to service **Settings**
2. Click **"Custom Domain"**
3. Add your domain (e.g., `api.yourdomain.com`)
4. Update DNS records as instructed
5. Render provides free SSL certificates

## Troubleshooting

### Build Fails

Check the build logs in Render dashboard. Common issues:
- Missing dependencies in `go.mod`
- Incorrect Dockerfile syntax
- Build timeout (increase in settings)

### Service Won't Start

1. Check environment variables are set correctly
2. Verify Appwrite credentials
3. Check logs for error messages
4. Ensure health endpoint returns 200 OK

### Redis Connection Issues

1. Verify Redis service is running
2. Check environment variables are linked correctly
3. Ensure both services are in the same region

### Slow First Request

This is normal on free tier due to spin-down. Upgrade to paid plan for always-on service.

## Local Development

Test the Docker setup locally before deploying:

```bash
# Build and run with Docker Compose
docker-compose up --build

# Test the API
curl http://localhost:8080/health

# Stop services
docker-compose down
```

## Security Best Practices

1. **Never commit `.env` file** - Already in `.gitignore`
2. **Use Render's secret management** - For API keys and secrets
3. **Enable HTTPS only** - Render provides this by default
4. **Rotate secrets regularly** - Update in Render dashboard
5. **Use environment-specific configs** - Different keys for dev/prod
